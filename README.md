## What we built

A financial plan only helps a family if they understand it. So we turned each family's report into an immersive 3D website you explore by scrolling: instead of reading their plan, the family moves around inside it.

When they arrive, the family sees the essentials on a single screen: their score, what is going well, what needs attention and the first recommended action. Then they choose what worries them today, and the journey starts there. Each area of the plan is an island:

| Island | What the family can do |
|---|---|
| **Savings & Expenses** | See how their income is split and adjust each part. Write their own goals in their own words ("a boat", "open a café"), which appear as 3D objects that build up as they save. |
| **Insurance & Protection** | A shield of rings (emergency fund, life insurance and liability cover) that fills according to their real coverage versus the recommended level. |
| **Debt Management** | A mountain (mortgage), a volcano (expensive debt) and a lake (available cash). Simulate extra payments and compare strategies to see when they become debt-free. |
| **Assets & Investments** | Their portfolio explained step by step, with a simple and an expert view, plus a growth simulator at 5, 10 and 20 years. |
| **Retirement & Goals** | A road from today to retirement, with each goal at its date, that plays out year by year. |

Also:
- **Investment Analysis:** a button on the summary opens a full portfolio analysis dashboard.
- **AI assistant:** answers any question about the report, typed or spoken, using only that family's own figures.

**One rule we never break:** the AI sets priorities and writes the copy, but it never makes up a number. Every figure comes from the family's data, and if something is missing, the site says so.

## How it works

```
app.py                 → server (FastAPI): data, AI and API
static/islands.html    → the whole website (HTML + Three.js) in a single file
cases/                 → family data (backup copy)
cases/_maps/           → island maps already generated by the AI (backup)
requirements.txt       → Python dependencies
render.yaml            → deployment configuration for Render
```

- **Data:** the server fetches each family's data through the **Sherpas MCP**. If the connection fails, it uses the copy in `cases/`.
- **AI:** with the team key, a model reads the family's data and profile, orders the islands by urgency and writes the copy. Each generated map is saved in `cases/_maps/`, so the site keeps working even when the AI is unavailable.
- **Families:** the family selector is built from what the API returns. No names are hard-coded.
- **Security:** keys live only on the server and never reach the browser.

**API**

| Route | Returns |
|---|---|
| `GET /` | The website |
| `GET /api/cases` | List of available families |
| `GET /api/case/{id}` | A family's full plan, including its island map |
| `POST /api/ask` | The assistant's answer to a question about the report |

## Run it locally

You need Python 3.10 or later.

```bash
git clone https://github.com/999adriana/InnovaTech.git
cd InnovaTech
python3 -m venv .venv
source .venv/bin/activate        # on Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Create a `.env` file in the project root with your keys (it is never committed):

```
MCP_URL=...
MCP_TOKEN=...
LLM_PROXY_URL=...
TEAM_KEY=...
```

Start the server and open **http://127.0.0.1:8000**:

```bash
uvicorn app:app --reload
```

> It also runs without keys, using the data and maps saved in `cases/`. The only thing that won't answer is the assistant.

## Deployment

The site is deployed on **Render** using the `render.yaml` in this repository. Every push to `main` deploys automatically. Keys are set as environment variables in Render, never in the code.
